# Animated spell effects — design

Date: 2026-08-13
Status: designed — not built

## What this is

The map table can hide a dungeon and point at it. This adds the third thing a DM does with a
map in front of players: set fire to part of it. An effect is an animated, transparent WebM —
a fireball, a lightning bolt, a cone of frost — placed on the map by dragging a box, played
once on both windows, and gone.

The animations are [Jack Kerouac's Animated Spell Effects](https://github.com/jackkerouac/animated-spell-effects),
376 files drawn top-down for exactly this use. They are **GPL-3.0**, which governs how much of
this design is about files and how little is about drawing.

## Play model

Unchanged from [the map table](2026-08-11-map-table-design.md): two windows, one machine, one
origin, `BroadcastChannel` between them. An effect is not fog — it is never stored with the
map, never part of a stroke, never in the undo stack. It happens and then it is over.

## Decisions

| Decision | Chosen | Rejected, and why |
|---|---|---|
| Where the files live | ~35 curated effects committed to `assets/spell-effects/`, ~28 MB | Fetching every effect from a CDN on demand — no repo weight, but the table needs internet at the moment a spell goes off, and a table with no internet is a table with no fireball |
| The other 341 | Indexed, searchable, fetched from jsDelivr on first use and cached in IndexedDB | Hiding them entirely — the pack is large and good, and an index costs kilobytes |
| Finding one | Search box over the whole index | A fixed palette of favourites: faster in combat, but reaching anything else means editing the page |
| Placing one | Drag a box, exactly like the fog rectangle | Aiming rays and cones along the drag vector — truer to how they were drawn, but a second gesture to learn mid-combat. The shape tag is in the index, so this can change later without touching the assets |
| Lifetime | Plays once, then gone | A loop-until-dismissed modifier — one more thing to forget to turn off in front of the players |
| Where the code lives | A new shared `assets/spellfx.js`, loaded by both pages | Putting it in `fog.js` — that file is the map's arithmetic and is pure; this one owns video elements and the network |
| Sound | None. Videos are muted | The pack is silent anyway, and muting is what lets a browser autoplay at all |

## The licence, which is the part that constrains the rest

GPL-3.0 assets in a public repository is redistribution, and redistribution has terms. This
design meets them rather than working around them:

- `assets/spell-effects/LICENSE` — the GPL-3.0 text, verbatim.
- `assets/spell-effects/CREDITS.md` — what was taken, from where, at which commit, and by whom.
- A credit line naming Jack Kerouac inside the effects panel, where a DM actually sees it, and
  a line in `README.md`.

Nothing here is a spoiler, which is why bundling is acceptable at all: the map table refuses to
commit *maps* because a public repo would let a player open a dungeon they have not reached. A
fireball gives nothing away.

## Where an effect is fetched from

One function, three sources, tried in order:

1. **Bundled** — `assets/spell-effects/<category>/<file>.webm`, same origin. No network, no
   taint, nothing to cache.
2. **Cached** — a blob in IndexedDB, store `fx`, keyed by the pack-relative path. This is where
   a previously fetched non-bundled effect lives, so the second cast works with the router
   unplugged.
3. **The CDN** — `https://cdn.jsdelivr.net/gh/jackkerouac/animated-spell-effects@<commit>/<path>`,
   which serves `Access-Control-Allow-Origin: *`. Fetched as a blob, stored in `fx`, played from
   an object URL — never handed to a `<video>` as a cross-origin URL, which would taint any
   canvas it is drawn into and break `getImageData` for the bench and the tests.

Pinned to a commit, not `@master`: an index that disagrees with the CDN is a 404 in front of
the players. The pin is `436fa96d7e9e97f8e6116c19c65f495d269f8093` — the pack's last commit,
May 2021, so in practice it has stopped moving; the pin costs nothing and removes the question.

## The index

`data/spell-effects.json`, generated by `scripts/fx-index.py` from the GitHub tree API:

```json
{ "commit": "…", "generated": "2026-08-13",
  "effects": [ { "path": "fire/fire_explosion_CIRCLE_01.webm", "name": "fire explosion",
                 "category": "fire", "shape": "circle", "kb": 533, "bundled": true } ] }
```

`shape` is parsed from the filename — the pack marks each file `CIRCLE`, `SQUARE`, `RAY`,
`CONE` or `RECTANGLE`. It is unused by the placing gesture today and is in the index anyway,
because it is free to record now and impossible to reconstruct later without re-reading 376
filenames.

## Casting

**Effects** in the toolbar opens a panel: a search box and a filtered list, bundled first, the
rest marked *fetch on first use*. Choosing one **arms** the table — the bar says which effect is
armed, and both windows preload it so the projector does not stutter on the first cast.

Armed, a left-drag draws a box with the same preview machinery as the fog rectangle, in a
different colour, and on release the effect plays stretched to fill that box. The table stays
armed for the next cast; **Escape** disarms, as does picking Reveal or Hide.

Space still means laser, and Space wins: a laser drag over an armed table pings and does not
cast. The fog tools are untouched.

## The channel

```js
{ t:"preload", path }                       // warm the projector's copy
{ t:"cast", path, rect:{x0,y0,x1,y1} }      // image space, like every other coordinate here
```

The rectangle is in image space for the reason every other rectangle is: the projector's canvas
is a different size, and a box in the sender's device pixels lands somewhere else on it.

No timestamp and no seeking. Each window plays its own copy from the beginning on receipt; the
projector may start a frame or two late, which nobody in a lit room can see.

## Drawing

`SpellFx` keeps the live casts — `{video, rect, url}` — and both pages call `SpellFx.draw(g, view)`
at the very end of `redraw()`, after the fog and after the laser. Effects belong on top of fog:
a DM sets fire to ground the players cannot see at least as often as ground they can.

A cast ends on the video's `ended` event, which drops it from the list and revokes its object
URL. While any cast is alive both pages need frames nothing else is asking for — the same
problem the ping already solved, so `animatePings` generalises to one loop that runs while
`pings.length || SpellFx.playing()`.

## Testing

`map-table.html?test=1`, in the house style — pure functions exercised without a canvas, a map
or a network:

- the search filter: matches name, category and shape; bundled sort first
- `shape` parsed from every filename form in the pack, including `RECTANGLE` and the unmarked
  files that have no shape at all
- resolution order: bundled path wins over cache, cache over CDN; the CDN URL carries the
  pinned commit
- the cast payload: image-space rect, structured-clonable, no device pixels
- box → canvas placement through a view, matching `previewBox`
- a finished cast leaves the live list, and the loop stops when the last one goes

## What this costs

~28 MB added to a repo that is about 40 MB today, permanently, and a GPL notice that has to
stay. Decode of a video under 1024 px is a fraction of a millisecond against the 7 ms the map
already costs, and effects only draw while one is playing.

## Deferred, deliberately

- Aiming rays and cones along the drag, which the `shape` tag already makes possible
- Looping effects for a burning wall or a lingering aura
- Token-following effects — there are no tokens on this table
- Any effect the DM has drawn themselves; the loader would be the map loader again
